## P0：提高可信度与维护效率

| 工作 | 目标验收 |
| --- | --- |
| 字段级来源与过期状态 | 时间、场馆、开售各自可查证据；抓取成功不会掩盖字段过期 |
| 冲突复核工作流 | 能在保留原始证据和版本记录的前提下审核、纠正并解除冲突；有权限与审计 |
| 来源结构漂移与候选保留 | fixtures 可重放；来源异常可定位；候选去重/归档后仍可解释发布依据 |
| 目录延迟与采集公平 | 对临近演出、关注艺人和一般目录分别展示分母、到期积压与延迟；不以健康来源比例替代准确率 |
| 新来源集成 | 有公开访问条件、预算、失败回退及 fixture，通过日期/身份边界测试 |

## P1：完善个人档案与原生端

| 工作 | 目标验收 |
| --- | --- |
| 私人资料生命周期 | 明确账号恢复、导出与删除策略，验证跨用户隔离和备份边界 |
| 原生账号与持久状态 | 专门的移动会话设计，离线/重启后记录保留；完成设备验收 |
| 隐私可控的分享 | 用户明确选择公开内容，分享投影不含票码、座位、精确未来行程与私密备注 |
| 通知投递 | 先有 transactional outbox、重试/幂等和投递记录，再实现邮件 / APNs；不是只有计划表 |
| 无障碍与视觉回归 | 关键路径有键盘、长文案、窄屏、缺图和减少运动证据 |

## 待验证的产品方向

高级跨城规划、年度回顾、订阅、披露明确的合作入口与更多市场都是假设。先访谈并观察真实用户的搜索 → 保存 → 出席行为，再决定是否建设。支付、自动购票、完整运营后台和全球全覆盖不属于当前能力。

优先依据用户影响、事实可信度与维护成本排序。对新方向先开功能建议；适合初次贡献的工作见[贡献指南](../CONTRIBUTING.md)。
